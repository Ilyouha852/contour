# Backend сервиса подбора контрагентов

REST API на FastAPI для поиска поставщиков по истории государственных закупок. Интерфейс пользователя не входит в этот сервис.

## Запуск

API запускается настроенным workflow проекта. Документация OpenAPI доступна по `/api/docs`, схема — `/api/openapi.json`, проверка — `/api/healthz`.

Данные и локальная база SQLite хранятся в `artifacts/api-server/data/`. Путь к базе можно изменить переменной `DATABASE_PATH`; каталог с начальными CSV — `data/source/`. При первом запуске три исходных файла загружаются автоматически. Пустые строки пропускаются, ИНН сохраняются текстом, повторные пары `lot_id × supplier_inn` объединяются, позиции сверх 50 на лот отбрасываются. ИНН в научной нотации принимаются только при корректной контрольной сумме; невосстановимые строки участников пропускаются с предупреждением, чтобы не создавать ложный ИНН. `/api/v1/stats` показывает покрытие, предупреждения и статистику последнего импорта (`rows_read`, `blank_rows`, `imported_rows`, `orphan_rows`).

## Основные запросы

### Импорт датасета

`POST /api/v1/datasets/import` — `multipart/form-data` с полями:

- `notices_file` — CSV извещений;
- `items_file` — CSV ТРУ;
- `suppliers_file` — CSV поставщиков, необязательный.

Этот endpoint заменяет исторический набор лотов. Перед загрузкой все файлы проверяются; при ошибке транзакция откатывается.

### Подбор

`POST /api/v1/recommendations`, JSON:

```json
{"lot_id":"4652711","top_k":20,"loss_weight":0.25}
```

Можно передать те же три CSV как multipart и `lot_id` для целевого лота. Загруженные в этом режиме лоты добавляются к текущей истории, а не стирают её. Если в переданном файле извещений ровно один лот, `lot_id` можно опустить — даже если в базе уже есть другие лоты.

Ответ содержит оценку, роль и уверенность, статус, МСП/риск-признак, взвешенные вклады и исходные значения факторов F1–F8, до трёх лотов-доказательств и текстовое объяснение.

### Остальные маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/stats` | Размер и версия текущего датасета |
| `GET` | `/api/v1/lots/{lot_id}` | Закупка и позиции ТРУ |
| `GET` | `/api/v1/suppliers?q=...` | Поиск поставщиков по ИНН/названию |
| `GET` | `/api/v1/suppliers/{inn}` | Карточка и история поставщика |
| `POST` | `/api/v1/batch/runs` | Пакетный пересчёт (до 40 000 лотов) |
| `GET` | `/api/v1/batch/runs/{run_id}` | Статус и прогресс пакета |
| `GET` | `/api/v1/batch/runs/{run_id}/export?format=xlsx` | XLSX с листами «Рекомендации» и «Объяснения» либо CSV |
| `POST` | `/api/v1/enrichment/refresh` | Офлайн-загрузка CSV реестров МСП и/или РНП |

Для защиты изменяющих данные маршрутов загрузки датасета и реестров задайте `ADMIN_TOKEN`; multipart-запрос подбора, который дополняет историю, также будет требовать заголовок `X-Admin-Token`. Backend ничего не скачивает из внешних источников самостоятельно. Каждое обновление МСП/РНП заменяет прежний снимок соответствующего реестра и обновляет версию данных; веса и параметры скоринга фиксируются в записи запуска.

## Ранжирование

Кандидаты берутся из участников более ранних закупок по близким кодам ОКПД2 и совпадению терминов названия и позиций ТРУ. Редкие термины получают больший IDF-вес, а текстовые частоты считаются только по лотам до даты целевой закупки. Совпадения по ОКПД2 имеют уровни 1.0 / 0.7 / 0.5 / 0.25. Формула `100 × M × Σ(wₖ × Fₖ)` включает:

| Фактор | Вес |
| --- | ---: |
| Опыт в категории | 0.30 |
| Победы в текстово-похожих лотах | 0.20 |
| Результативность | 0.15 |
| Победы у этого заказчика | 0.10 |
| Соответствие цены | 0.08 |
| Актуальность побед | 0.07 |
| География | 0.05 |
| МСП-признак | 0.05 |

Активная запись в РНП даёт множитель `M=0` и статус «Риск». При ограниченной истории применяется штраф `min(1, 0.6 + 0.1 × число лотов)`; кандидат только из реестра МСП дополнительно ограничен множителем 0.8. Значение `loss_weight` по умолчанию — 0.25; 0 исключает проигранные участия из опыта.

Все зависимости логики — локальные Python-пакеты и SQLite; внешние API нейросетей, поисковые сервисы и ключи не требуются. SQLite и локальный токенный индекс используются вместо требуемых в исходной целевой архитектуре PostgreSQL и Elasticsearch, чтобы этот backend запускался автономно в данном проекте. Для многопользовательской/высоконагруженной эксплуатации потребуется миграция хранилища и отдельная оценка времени пакетной обработки.

## Текущий набор данных

В корне рабочего пространства находятся исходные CSV за 2024–2025 годы: 604 452 извещения, 2 971 651 строка позиций ТРУ и 1 010 138 строк участников. Все позиции сохраняются при импорте; повреждённые или невосстановимые ИНН участников пропускаются с предупреждением, а не подменяются предположительными значениями. Фактическое число загруженных и отброшенных строк доступно в `/api/v1/stats` (`last_ingestion_summary` и `ingestion_warnings`).

Снимки реестров МСП и РНП в комплект не входят — для их использования нужна офлайн-загрузка через `/api/v1/enrichment/refresh`. HTTP-загрузка CSV ограничена 25 МБ на файл; корневой архив загружается локально, не через этот endpoint. Данные за 2024–2025 годы дают историческую основу для подбора, но сами по себе не подтверждают качество рекомендаций на более поздних периодах.
