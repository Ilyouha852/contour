# Backend сервиса подбора контрагентов

REST API на FastAPI для поиска поставщиков по истории государственных закупок. Интерфейс пользователя не входит в этот сервис.

## Запуск

API запускается настроенным workflow проекта. Документация OpenAPI доступна по `/api/docs`, схема — `/api/openapi.json`, проверка — `/api/healthz`.

Закупки и история участников хранятся в SQLite в `artifacts/api-server/data/`. Реестры МСП и РНП не загружаются в базу: сервис проверяет контрагентов в публичном поиске ФНС и ЕИС по сети. Пустые строки CSV пропускаются, ИНН сохраняются текстом, повторные пары `lot_id × supplier_inn` объединяются, позиции лотов сохраняются. Невосстановимые ИНН участников пропускаются с предупреждением. `/api/v1/stats` показывает покрытие, предупреждения и статистику последнего импорта.

## Основные запросы

### Импорт датасета

`POST /api/v1/datasets/import` — `multipart/form-data` с полями:

- `notices_file` — CSV извещений;
- `items_file` — CSV ТРУ;
- `suppliers_file` — CSV поставщиков, необязательный.

Этот endpoint заменяет исторический набор лотов. Перед загрузкой все файлы проверяются; при ошибке транзакция откатывается.

### Подбор

`POST /api/v1/recommendations`, JSON:

```json
{"lot_id":"4652711","top_k":20,"loss_weight":0.25}
```

Можно передать те же три CSV как multipart и `lot_id` для целевого лота. Загруженные в этом режиме лоты добавляются к текущей истории, а не стирают её. Если в переданном файле извещений ровно один лот, `lot_id` можно опустить — даже если в базе уже есть другие лоты.

Ответ содержит оценку, роль и уверенность, основания классификации (`role_source`, `role_signals`), статусы МСП/РНП, сведения об источнике и времени онлайн-проверки, вклады и значения F1–F8, до трёх лотов-доказательств и текстовое объяснение. Сходство ОКПД2 считается по нормированным весам всех позиций лота, а не по лучшему одиночному совпадению.

### Остальные маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/stats` | Размер и версия текущего датасета |
| `GET` | `/api/v1/lots/{lot_id}` | Закупка и позиции ТРУ |
| `GET` | `/api/v1/suppliers?q=...` | Поиск поставщиков по ИНН/названию |
| `GET` | `/api/v1/suppliers/{inn}` | Карточка и история поставщика |
| `POST` | `/api/v1/batch/runs` | Пакетный пересчёт (до 40 000 лотов) |
| `GET` | `/api/v1/batch/runs/{run_id}` | Статус и прогресс пакета |
| `GET` | `/api/v1/batch/runs/{run_id}/export?format=xlsx` | XLSX с листами «Рекомендации» и «Объяснения» либо CSV; в объяснениях — snapshot источников |
Для защиты изменяющих данные маршрутов загрузки датасета задайте `ADMIN_TOKEN`; multipart-запрос подбора, который дополняет историю, также будет требовать заголовок `X-Admin-Token`. Полные реестры не сохраняются. В рекомендации и пакетном экспорте записывается только компактный snapshot конкретного кандидата: статус, полученные факты, URL источника и время проверки. Сетевая ошибка или недоверенный TLS-сертификат дают `unknown`, а не подтверждение отсутствия записи.

## Ранжирование

Сначала выбираются поставщики с точными совпадениями ОКПД2, затем с родственными кодами и текстово-похожей историей; новые MSP-кандидаты добавляются в слабых категориях через поиск ФНС по ОКВЭД/региону. F1 — затухающий исторический опыт, взвешенный по покрытию всех позиций; позиции без кода остаются в знаменателе. F2 — IDF-взвешенная похожесть прошлых побед, умноженная на покрытие позиций. Совпадения кодов имеют уровни 1.0 / 0.7 / 0.5 / 0.25. Формула `100 × M × Σ(wₖ × Fₖ)` включает:

| Фактор | Вес |
| --- | ---: |
| Опыт в категории | 0.30 |
| Победы в текстово-похожих лотах | 0.20 |
| Результативность | 0.15 |
| Победы у этого заказчика | 0.10 |
| Соответствие цены | 0.08 |
| Актуальность побед | 0.07 |
| География | 0.05 |
| МСП-признак | 0.05 |

Активная запись в РНП даёт множитель `M=0` и статус «Риск». При ограниченной истории применяется штраф `min(1, 0.6 + 0.1 × число лотов)`; кандидат только из реестра МСП дополнительно ограничен множителем 0.8. Значение `loss_weight` по умолчанию — 0.25; 0 исключает проигранные участия из опыта. Для каждого результата возвращаются `msp_status` и `risk_status`: `member`/`listed`, `not_member`/`clear` либо `unknown`. Роль сопровождается `role_source` и `role_signals`. Provenance `enrichment` содержит факты, URL источника и `checked_at`; общее состояние источников находится в `registry_checks`.

Скоринговая логика выполняется локально и не зависит от API нейросетей. Проверка реестров при обычной рекомендации обращается к публичным сайтам ФНС и ЕИС; для временного бэктеста эти вызовы отключены. TLS-проверка сертификатов включена через системное хранилище Windows (`truststore`); если сертификат ЕИС не доверен, статус РНП остаётся `unknown`, и нужно установить доверенный корневой сертификат в ОС. SQLite и локальный токенный индекс используются вместо целевой архитектуры PostgreSQL/Elasticsearch; для высокой нагрузки потребуется отдельная оценка масштабирования.

## Оценка качества

Запустите временной бэктест из `artifacts/api-server`:

```powershell
python -m app.evaluation --start 2025-07-01 --end 2026-01-01 --max-lots 100 --top-k 10
```

`--start` включается, `--end` не включается. Лоты выбираются равномерно по времени из периода, а признаки и кандидаты для каждого лота строятся только по более ранней истории. Реестры отключены, результаты не сохраняются. Отчёт содержит Hit@10, Recall@10, nDCG@10 и MRR модели и baseline «частые победители в близких ОКПД2», а также Recall@300 пула кандидатов и долю фактических победителей с доступной предшествующей историей. Для приемочного вывода увеличьте `--max-lots` и зафиксируйте период/выборку; маленькая выборка годится только для smoke-проверки.

**Измеренный smoke-бэктест:** 25 лотов за 2025-H2: Hit@10 0.40 против 0.28 у baseline; nDCG@10 0.352 против 0.113. Это предварительный сигнал на небольшой выборке, а не подтверждение приемочного качества.

**Расширенная выборка:** 50 равномерно выбранных лотов за 2025-H2: Hit@10 0.30 против 0.22; nDCG@10 0.243 против 0.115; Recall@300 пула кандидатов 0.72; у 94% победителей была предшествующая история. В отчёте также фиксируются версия данных, веса/параметры и хэш выборки. Метрики диагностические и требуют ручной проверки перед приемочным выводом.

## Текущий набор данных

В корне рабочего пространства находятся исходные CSV за 2024–2025 годы: 604 452 извещения, 2 971 651 строка позиций ТРУ и 1 010 138 строк участников. Все позиции сохраняются при импорте; повреждённые или невосстановимые ИНН участников пропускаются с предупреждением, а не подменяются предположительными значениями. Фактическое число загруженных и отброшенных строк доступно в `/api/v1/stats` (`last_ingestion_summary` и `ingestion_warnings`).

Реестр МСП проверяется через публичный поиск ФНС, РНП — через публичную страницу поиска ЕИС. Их веб-интерфейсы не предоставляют стабильный документированный API; формат может измениться, а доступ зависит от сети и TLS-сертификатов. При недоступности РНП рекомендация сохраняется, но её статус риска будет `unknown`. CSV-загрузка через HTTP ограничена 25 МБ на файл; полные исходные CSV импортируются локально. Данные закупок за 2024–2025 годы дают историческую основу для подбора, но сами по себе не подтверждают качество рекомендаций на более поздних периодах.
